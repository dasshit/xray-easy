# План unit-тестирования web

## Текущее состояние

Проверено 28 сентября 2026 года. В `web/package.json` есть только `dev` и
`build`; Vitest, тестового окружения, отчёта о покрытии и web-job в CI нет.
В `web/src` нет тестов. Текущий `vite build` собирает приложение, но не
проверяет пользовательские сценарии и не запускает отдельную проверку типов.
Поэтому исходная точка — **0 web-тестов**; процент покрытия пока **не измерен**.

Исполняемый код распределён так:

| Файл | Что требует проверки |
| --- | --- |
| `domain/models.ts` | Выбор действия для профиля и доступность включения; остальные объявления — только типы. |
| `application/ui.ts` | Выбор и сохранение темы/языка, форматирование трафика и времени. |
| `infrastructure/api.ts` | HTTP-запрос, успешный и ошибочный ответ, ошибка сети. |
| `App.vue` | Первичная настройка, вход, четыре раздела панели, модальные окна, операции с профилями, настройками, TOTP, backup, диагностика и SSE. |
| `main.ts` | Подключение корневого компонента; отдельный smoke-test, если он полезен для общего отчёта. |

`style.css`, SVG и статический HTML не имеют осмысленного unit-покрытия.
Визуальную компоновку, адаптивность, реальные браузеры и связку с Go API
проверять отдельно; DOM-тесты не заменяют эти проверки.

## Инструменты и метрика

Добавить Vitest с Vue Test Utils, `jsdom` и `@vitest/coverage-v8`, подобрав
совместимые версии с Vite 6.4.3 из lockfile и Node 24 из Dockerfile. Проверить
типы через `vue-tsc --noEmit`. Не переписывать интерфейс ради тестового
фреймворка: компонентные тесты монтируют настоящий `App.vue` и взаимодействуют
с полями/кнопками, сетевую границу и браузерные API подменяют в тесте.

Предусмотреть команды `npm test` (одноразовый запуск), `npm run test:watch`,
`npm run test:coverage` и `npm run typecheck`. Покрытие считать для всех
рукописных исполняемых `src/**/*.{ts,vue}`, включая файлы, которые тесты не
импортировали. Исключить только тесты, декларации типов, CSS, статику и
сгенерированные файлы. Хранить отчёты локально в игнорируемом каталоге
`web/coverage/`; в CI печатать краткую сводку и сохранять отчёт как артефакт.
Для `App.vue` отдельно смотреть покрытие ветвей: длинные строки шаблона делают
один только процент строк малоинформативным.

После первой работающей пачки тестов зафиксировать фактическую базу в этом
документе. Порог включать поэтапно, чтобы CI не проходил за счёт исключения
основного компонента. Конечная цель: не ниже **90% строк и операторов** и
**85% ветвей и функций** по исполняемому web-коду; для `App.vue`, `ui.ts`,
`api.ts` и функций домена — не ниже **80% строк на каждый файл**. Эти числа
являются регрессионным барьером, а не заменой проверки критических сценариев.
Если карта покрытия Vue SFC показывает служебный сгенерированный код, сначала
проверить remapping и документировать исключение, не снижая порог молча.

## Порядок реализации

Каждый этап: тесты наблюдаемого поведения, повторный отчёт покрытия,
`npm run typecheck`, `npm run build` и отдельный коммит. Небольшие изменения
кода допустимы, когда тест обнаружил ошибку или нужна узкая точка внедрения
зависимости. Проверки не должны обращаться к работающему серверу и не должны
зависеть от реальных часов, языка или часового пояса машины.

### 1. Каркас, чистые функции и HTTP-адаптер

- Подключить runner, DOM-окружение, coverage и CI-job с `npm ci`.
- `domain/models.ts`: разрешённые переходы enabled/disabled/revoked.
- `application/ui.ts`: приоритет сохранённого значения над системным,
  английский fallback, тема, граничные значения байтов около 1024 и единиц,
  отсутствие даты и дата при фиксированном часовом поясе.
- `infrastructure/api.ts`: метод/тело/заголовки, JSON-ответ, структурированная
  ошибка с `code`, ответ без JSON, ошибка `fetch`.
- Зафиксировать первую реальную сводку lines/statements/branches/functions.

### 2. Запуск и аутентификация

- Ненастроенный сервер: поле порта приходит из `/api/setup/status`, отправка
  данных настройки ведёт к форме входа, отказ оставляет возможность повтора.
- Настроенный сервер: успешное `/api/me` загружает данные панели; отсутствие
  сессии показывает вход; ошибка первоначальной загрузки видима пользователю.
- Парольный вход, ответ `totp_required`, переключение между TOTP и recovery,
  успешный/неуспешный код, возврат `busy` после ошибок.
- Выход и «выйти со всех сессий»: правильный запрос, закрытие SSE и очистка
  авторизованного состояния; ошибка не должна ложно показывать выход.

### 3. Профили

- Пустой список, карточки, статус, объём трафика, last seen, локализация.
- Модалка создания: имя видно и редактируется, кнопка неактивна при пустом
  имени, fingerprint по умолчанию/явный, успешное создание добавляет ровно
  одну карточку и открывает выданный профиль; при ошибке список не меняется.
- QR, VLESS-ссылка, JSON download и повторное открытие профиля; успешное и
  неуспешное копирование ссылки.
- Enable/disable/revoke: точный API-запрос после подтверждения, отмена кнопкой,
  Escape и фоном, обновление нужной карточки только после успеха; отозванный
  профиль больше нельзя использовать.

### 4. Настройки, безопасность и диагностика

- Загрузка настроек, preview изменений, diff/последствия, требуемое точное
  подтверждение, apply и повторная загрузка настроек/профилей; отказ apply
  сохраняет данные для повторной попытки, отмена не применяет изменение.
- Backup: имя успешной копии и ошибка. TOTP: получение QR и recovery-кодов,
  подтверждение кода, обновление статуса, отключение с паролем и кодом,
  возврат к экрану входа. Не записывать секреты TOTP в localStorage.
- Состояние Xray и fallback при ошибке, объединение логов двух источников при
  частичном отказе, сортировка и ограничение последних 100 записей, счётчики
  ошибок/предупреждений. Проверить оба встречающихся обозначения уровня:
  `warn` и `warning`.

### 5. События, устойчивость и барьер покрытия

- Поддельный `EventSource`: `stats` обновляет профили, `status` обновляет
  состояние и логи, ошибка вызывает один отложенный reconnect; logout и
  unmount закрывают соединение и не оставляют активный reconnect.
- Проверить изоляцию тестов: после каждого теста восстановить `fetch`,
  `EventSource`, clipboard, localStorage, `matchMedia` и fake timers; ждать
  Vue render и завершение promises, не использовать реальные sleep.
- Добрать недостающие значимые ветви, включить конечные coverage thresholds
  и запуск в CI: `npm ci`, `npm run typecheck`, `npm test`,
  `npm run test:coverage`, `npm run build`. Отчёт приложить к CI.

## Критерий завершения

Все перечисленные сценарии проходят локально и в CI без живого бэкенда;
покрытие достигает порогов, а отчёт включает `App.vue` и ранее не вызванные
исполняемые модули. Изменения в API-контракте или найденные баги отражены в
тестах. После этого отдельно можно добавить browser E2E для установки,
логина, выдачи профиля и реального SSE; он не входит в unit-метрику.
